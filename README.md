# متصفح السكربتات — Flutter / Android

نسخة أولية: متصفح داخل التطبيق، جلب ملفات JavaScript من GitHub، محرر، تشغيل يدوي، نتائج قابلة للنسخ وحفظ إعدادات المستودع والكود محليًا.

## الاستخدام

1. افتح التطبيق. توجد صفحة تجريبية وزر لتجربة السكربت الافتراضي.
2. افتح الموقع المطلوب من شريط العنوان.
3. اضغط أيقونة السحابة وأدخل `owner/repo` واسم الفرع والمجلد، مثل `scripts`.
4. اختر ملف `.js` وراجع الكود، ثم اضغط حفظ وإغلاق وبعدها تشغيل.
5. لإحضار التحديثات افتح قائمة GitHub واختر الملف من جديد. لا يوجد تشغيل تلقائي.

ارفع محتويات هذا المشروع إلى جذر مستودعك. مجلد `scripts` يحتوي أمثلة للضغط واستخراج الروابط وانتظار عنصر. يمكن أن يكون مستودع السكربتات مختلفًا عن مستودع التطبيق. يدعم المستودعات العامة حاليًا فقط.

## صيغة السكربت

الملف يُنفّذ كجسم دالة async في الصفحة المفتوحة، ويمكن استخدام `await` و`return`. استخدم `return` لقيمة قابلة للتحويل إلى JSON. السكربتات التقليدية التي لا تستخدم return ستعمل، وتعرض رسالة نجاح بدون قيمة إرجاع.

```javascript
const button = document.querySelector('#download');
if (!button) throw new Error('الزر غير موجود');
button.click();
return 'تم الضغط';
```

تشغيل الأكواد يدوي. السكربت يستطيع الوصول لبيانات الصفحة المتاحة لجافاسكربت، لذلك راجع الكود قبل تشغيله. النقر لا ينتظر ظهور العنصر تلقائيًا؛ استخدم مثال `wait-and-click.js`. قيود المتصفح تنطبق على iframes والنوافذ والإجراءات التي تتطلب لمسة فعلية. السكربت الذي يغير الصفحة قد ينفذ بنجاح دون أن يرجع نتيجة. مهلة انتظار النتائج 30 ثانية، ولا توقف حلقة JavaScript متزامنة لا نهائية. تحميل الصفحة من جديد يزيل سياق السكربت المعتاد.

## بناء APK محليًا

ثبّت Flutter stable وAndroid SDK وJava حسب `flutter doctor`، ثم:

```sh
flutter pub get
flutter analyze
flutter test
flutter build apk --debug
```

الناتج: `build/app/outputs/flutter-apk/app-debug.apk`. هذه نسخة تجريبية موقعة بمفتاح debug. للنشر يلزم إعداد توقيع release خاص بك.

## البناء بواسطة GitHub

بعد رفع ملفات المشروع بما فيها `.github/workflows/android.yml` إلى جذر مستودع GitHub: افتح Actions، اختر Build Android APK، ثم Run workflow. بعد نجاح العملية حمّل `script-browser-apk` من Artifacts، فك الضغط وانقل APK لهاتفك لتثبيته.

## حدود النسخة

- Android فقط، الحد الأدنى Android 7 / API 24.
- لا تتضمن رفع JSON إلى GitHub بعد؛ النسخة الحالية لتحميل السكربتات وتشغيلها وعرض النتائج.
- لا يوجد دعم رفع ملفات أو تنزيلات أو نوافذ منبثقة متعددة في المتصفح.
- GitHub قد يحد الطلبات دون تسجيل دخول. الأخطاء تظهر داخل التطبيق.

## التحقق في بيئة التطوير

تم بناء نسخة Android وتشغيلها على Samsung SM-S908N. نجحت اختبارات الوحدة الثمانية، كما نجح اختبار WebView على الهاتف: حظر طلب إعلاني، إخفاء عنصر إعلان، استمرار عمل JavaScript وزر عادي، منع رابط نافذة جديدة من تغيير الصفحة، وظهور العنصر الإعلاني عند استثناء الموقع. يمكن إعادة الاختبار باستخدام `flutter test integration_test/ad_blocker_test.dart -d DEVICE_ID`. تحليل Flutter انتهى دون ملاحظات.

## حماية الإعلانات

اضغط أيقونة الدرع أعلى المتصفح. الحماية مفعلة افتراضيًا وتشمل حظر الطلبات إلى قائمة محلية من نطاقات الإعلان والتتبع، وحظر النوافذ الجديدة، وإخفاء عناصر ذات علامات إعلانية معروفة. يعرض مربع الحماية عدد الطلبات والنوافذ المحظورة في الصفحة الحالية. لا تدخل العناصر المخفية ضمن هذا العدد.

يمكن تعطيل الحماية بالكامل أو استثناء اسم المضيف الحالي فقط أو إضافة نطاقات حظر مخصصة (نطاق في كل سطر، بدون https أو مسار). تتضمن القاعدة النطاق ونطاقاته الفرعية. حفظ الإعدادات يعيد تحميل الصفحة. الإعدادات محفوظة على الجهاز ولا ترسل سجل التصفح إلى خدمة خارجية.

القائمة المدمجة محدودة ومحلية وليست اشتراك EasyList أو نظام تعلم آلي. قد تفلت إعلانات مقدمة من نفس الموقع أو نطاقات جديدة، ولا تمنع الحماية كل التنقلات المزعجة داخل الصفحة. الحماية لا تحظر جميع النطاقات الخارجية حتى تبقى مشغلات الفيديو وتسجيل الدخول والسكربتات المعتادة قابلة للعمل. النوافذ الجديدة محظورة أثناء تفعيل الحماية، بما فيها بعض الروابط المشروعة؛ يمكن استخدام استثناء الموقع عند الحاجة. قد تمنع سياسة CSP الخاصة بالموقع بعض قواعد إخفاء العناصر.

مرجع واجهة المتصفح: https://inappwebview.dev/docs/webview/in-app-webview/

تم تثبيت نسخة `flutter_inappwebview 6.2.0-beta.3` تحديدًا لأنها تتضمن إصلاح إعداد ProGuard اللازم لأدوات AGP 9 المستخدمة في المشروع. ملف `pubspec.lock` مرفق لتكرار البناء بنفس الاعتماديات.
